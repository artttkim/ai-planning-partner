# 검수

## 경로와 엔진

- 지금 폴더가 플랜윗 작업 공간일 때만 진행한다. 아니면 파일을 건드리지 않고 작업 공간을 열어 달라고 한 줄로 안내한다 (`pw-standards` 9장).
- 이 스킬의 기본 폴더에서 두 단계 위가 플러그인 루트(`PLUGIN_ROOT`)다.
- 엔진 실행: `python "<PLUGIN_ROOT>/engine/run.py" <명령>` (`python`이 안 되면 `py`).

## 보여 주기

`01_검수함.md`의 검수 대기 항목을 단계별로 짧게 보여 준다.

- 결정 필요가 있는 단계를 먼저, 그다음 확인만 있는 단계를 보여 준다.
- 단계마다 요약 1~2줄, 결정 필요 질문과 선택지, 추천(현재 적용 중)을 보여 준다.
- 확인만은 한 줄씩 묶어서 보여 준다.
- 문서 전체를 보여 주지 않는다. 기획자가 원하면 그때 보여 준다.
- 마지막에 답하는 방법을 한 줄로 안내한다. 예: "화면 설계 1번은 A, 나머지 승인"처럼 답해 주세요.

## 답 반영

1. 결정과 수정 요청을 `00_과제요약.md`의 "결정 기록" 장에 남긴다 (날짜, 결정, 이유, 출처: 검수).
2. 추천안과 다르게 정해진 결정은 원본을 고치고, ID 연결을 따라 영향받는 다른 원본도 함께 고친다.
3. 화면 설계 원본이 바뀌었으면 엔진 `validate`와 `build all`을 다시 실행한다.
4. 답한 단계의 상태를 `00_과제요약.md`에서 "검수 완료"로 바꾸고, `01_검수함.md`의 해당 항목을 `## 검수 완료` 장 아래로 옮긴다.
5. 기획자가 언급하지 않은 "확인만" 항목은 승인으로 본다. 언급하지 않은 "결정 필요" 항목은 대기로 남긴다.
6. 반영 결과를 한두 줄로 알린다. 바뀐 파일만 말한다.
7. 모든 단계가 "검수 완료"가 되면 "개발에 전달할까요?"라고 한 줄로 묻는다. 그러자고 하면 `handoff` 스킬을 따른다.
