# 단계 진행

## 경로와 엔진

- 지금 폴더가 플랜윗 작업 공간일 때만 진행한다. 아니면 파일을 건드리지 않고 작업 공간을 열어 달라고 한 줄로 안내한다 (`pw-standards` 9장).
- 이 스킬의 기본 폴더에서 두 단계 위가 플러그인 루트(`PLUGIN_ROOT`)다.
- 엔진 실행: `python "<PLUGIN_ROOT>/engine/run.py" <명령>` (`python`이 안 되면 `py`).

## 순서

### 1. 과제 고르기

기획자가 과제를 말하지 않았으면 `과제/` 중 상태가 "진행 중"이고 가장 최근에 바뀐 과제를 쓴다. 진행 중 과제가 여럿이면 어느 과제인지 한 줄로 밝히고 진행한다.

### 2. 단계마다

`00_과제요약.md`의 진행 단계 중 상태가 "대기" 또는 "준비 중"인 단계를 순서대로 모두 진행한다. 건너뛰지 않는다. 앞 단계가 뒤 단계보다 늦게 작성되면, 이미 만든 뒤 단계 원본과 어긋나는 곳을 함께 고친다. 단계 번호 `NN`은 진행 단계 표의 순서다.

1. 단계 상태를 "작성 중"으로 바꾼다.
2. 단계를 작성한다.
   - 화면 설계: `pw-screen-design` 스킬을 따른다.
   - 그 밖의 단계: 아래 "기본 작성" 표에 따라 `2_기획문서/NN_<단계>.md`를 쓴다. 공통 기준은 `pw-standards`를 따른다.
3. `checker` 서브에이전트에 단계 이름과 원본 경로를 주고 점검받는다. 돌아온 질문은 원본을 보강해 해결한다. 해결할 수 없는 것만 검수함에 올린다.
4. 화면 설계 단계는 엔진으로 검사하고 파일을 만든다.
   - `validate "<과제>"` → 나온 문제를 고친다
   - `build all "<과제>"`
   - 파일이 열려 있어 실패하면, 기획자에게 파워포인트를 닫아 달라고 한 줄로 알리고 나머지 단계는 계속한다.
5. `pw-standards` 7장 형식으로 `01_검수함.md`에 올리고 단계 상태를 "검수 대기"로 바꾼다.
6. 결정 필요 항목은 추천안을 적용한 채로 다음 단계로 간다. 기획자를 기다리지 않는다.

단계 사이에 진행 상황을 길게 말하지 않는다. 한 단계가 끝날 때 한 줄이면 된다 (예: "영향 분석을 검수함에 올렸어요. 이제 화면 설계를 쓸게요.").

### 기본 작성

전용 모듈이 아직 없는 단계는 아래 내용으로 마크다운 원본을 만든다. 기획자에게 "준비 중"이라고 말하지 않는다. 원본 맨 위에만 `> 기본 작성`이라고 적는다.

| 단계 | 원본 | 담을 내용 |
|---|---|---|
| 영향 분석 | `NN_영향분석.md` | 바뀌는 기능이 영향을 주는 화면, 정책, 데이터, 다른 부서. 영향마다 근거와 대응 |
| 유저 플로우 / IA | `NN_유저플로우.md` | 바뀌거나 새로 생기는 흐름(mermaid flowchart), 화면 ID, 분기 조건. 메뉴 구조가 바뀌면 IA |
| 기능 명세 / 정책 | `NN_기능명세_정책.md` | 정책마다 정책 ID, 대상 화면, 조건과 값(단위 포함), 예외, 근거, 합의 상태. 화면 설계에서 만든 정책 ID를 모두 채운다 |
| 수용 기준 | `NN_수용기준.md` | 기능과 정책마다 `AC-` ID, Given/When/Then. 합의되지 않은 값은 `TBD` |
| 개발 태스크 | `NN_개발태스크.md` | `TASK-` ID, 작업 내용, 관련 AC, 선행 태스크. 합의 상태가 "합의"가 아닌 항목은 "합의 대기"로 표시 |

### 3. 모든 단계를 마치면

한 번만 알린다.

- 만든 파일 위치: `3_결과물/기획안.html`(눌러 보는 기획안, 개발 보기 포함), `3_결과물/개발명세.md`(개발자, AI 코딩 도구용)
- 검수할 것: 단계별 결정 필요 항목이 몇 개인지, 가장 중요한 결정 하나
- "검수할 거 보여 줘"라고 하면 볼 수 있다는 안내
