# 자료 반영

## 경로와 엔진

- 지금 폴더가 플랜윗 작업 공간일 때만 진행한다. 아니면 파일을 건드리지 않고 작업 공간을 열어 달라고 한 줄로 안내한다 (`pw-standards` 9장).
- 이 스킬의 기본 폴더에서 두 단계 위가 플러그인 루트(`PLUGIN_ROOT`)다.
- 엔진 실행: `python "<PLUGIN_ROOT>/engine/run.py" <명령>` (`python`이 안 되면 `py`).

## 순서

1. 새 자료를 보관한다. 붙여 넣은 글은 `00_과제요약.md`의 "받은 요청 원문" 장 아래에 `### 추가 <YYYY.MM.DD>`로 덧붙이고, 파일은 `1_입력자료/`에 저장한다. 문서는 `start` 스킬처럼 텍스트를 뽑는다.
2. `00_과제요약.md`와 원본을 비교해 바뀌는 항목을 찾는다.
3. 바뀌는 정도에 따라 처리한다.

| 바뀌는 정도 | 처리 |
|---|---|
| 가정이 확정되거나 `TBD`가 채워짐 | 바로 반영하고 알림 |
| 승인된 요약의 기능이나 범위가 바뀜 | 추천안으로 반영하고 검수함 결정 필요에 올림 |
| 흐름, 메뉴 구조, 화면 수가 바뀜 | 반영 전에 영향(바뀌는 화면)과 더 단순한 안을 한 줄로 말하고 답을 받는다. 반영할 때는 유저 플로우부터 다시 쓰고 화면을 새 목록대로 다시 그린다. 덧대지 않는다 (`pw-standards` 6장 "큰 변경") |
| 과제 유형이 바뀔 만큼 큼 | 요약을 다시 보여 주고 확인받음 |

4. ID 연결을 따라 영향받는 원본을 함께 고친다. 회의 결과로 합의된 항목은 합의 상태를 "합의"로 바꾼다.
5. 화면 설계 원본이 바뀌었으면 엔진 `validate`와 `build all`을 다시 실행한다.
6. `00_과제요약.md`의 변경 이력과 결정 기록에 남긴다. 이름이 바뀌거나 버린 개념은 "쓰지 않는 말"에 `- <옛말> → <새말>`로 더한다. 엔진 `validate`가 문서에 남은 옛말을 잡는다.
7. 바뀐 산출물을 한 줄씩 알린다.
