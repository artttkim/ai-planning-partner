# 내보내기

## 경로와 엔진

- 지금 폴더가 플랜윗 작업 공간일 때만 진행한다. 아니면 파일을 건드리지 않고 작업 공간을 열어 달라고 한 줄로 안내한다 (`pw-standards` 9장).
- 이 스킬의 기본 폴더에서 두 단계 위가 플러그인 루트(`PLUGIN_ROOT`)다.
- 엔진 실행: `python "<PLUGIN_ROOT>/engine/run.py" <명령>` (`python`이 안 되면 `py`).

## 순서

1. 과제를 고른다 (말하지 않았으면 가장 최근에 바뀐 진행 중 과제).
2. 엔진 `detect "<작업 공간>"`을 먼저 실행한다. 직접 고친 내용이 나오면 원본에 반영한 뒤 진행한다. 반영하지 않고 다시 만들면 직접 고친 내용이 사라지기 때문이다.
3. `validate "<과제>"`로 검사하고 문제를 고친다.
4. 버전: 기획자가 말한 버전을 쓴다. 구성원 합의 후라고 하면 `v1.0`. 말하지 않았으면 지금 버전을 유지한다 (`--version v0.2`처럼 넘긴다).
5. `build all "<과제>"`로 기획안과 개발 명세를 만든다.
6. 기획자가 화면 설계서(.pptx)를 요청했으면 `build pptx "<과제>" --version <버전>`도 실행한다.
   - 개발 보기를 요청했으면 `build dev "<과제>"`를 먼저 실행하고 `build all`을 다시 실행한다. 기획안에 개발 보기가 생기고, 그 뒤로는 기획을 고칠 때마다 함께 갱신된다. 수용 기준과 개발 태스크는 쓰지 않는다 (개발 전달 때 `handoff`).
   - "개발 보기 꺼 줘"라고 하면 `3_결과물/개발명세.md`를 지우고 `build all`을 다시 실행한다.
7. 만든 파일 위치를 알린다. 파일이 열려 있어 실패하면 파워포인트를 닫아 달라고 알린다.
