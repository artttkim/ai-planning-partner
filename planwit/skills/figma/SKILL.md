# 피그마로 보내기

플랜윗의 화면은 평소에는 기획안(HTML)으로 빠르게 고치고, 검수가 끝나면 이 스킬로 한 번에 피그마 디자인을 만든다. 고칠 때마다 피그마에 그리면 시간과 비용이 크기 때문이다.

## 지켜야 할 것

- **원본 피그마 파일은 읽기만 한다.** 회사 디자인 파일, 서비스 화면 파일에 쓰기 기능(`use_figma`, 업로드 등)을 쓰지 않는다. 그리기는 이 스킬이 새로 만든 파일에서만 한다.
- 새 파일은 기획자의 드래프트나 기획자가 정한 프로젝트에 만든다.
- 피그마 연결이 없거나 한도에 걸리면 멈추고 그대로 알린다. 보기(View) 좌석은 한 달 호출 수가 매우 적어 이 스킬을 쓸 수 없다. Dev 좌석은 읽기만, Full 좌석이어야 새 파일에 그릴 수 있다. 한도는 파일이 속한 팀의 좌석 기준이다.

## 순서

1. 과제를 고른다. 화면 설계 단계가 "검수 완료"가 아니면 그대로 보낼지 한 번만 묻는다.
2. 피그마 도구의 `whoami`로 좌석과 요금제를 확인한다. Full 좌석이 아니면 위 안내를 하고 멈춘다.
3. 피그마 지침 스킬(`figma-use`, `figma-generate-design`, 새 파일이면 `figma-create-new-file`)을 먼저 읽는다.
4. 디자인 기준을 찾는다 (읽기만).
   - 회사 디자인 시스템 라이브러리를 검색해 부품(버튼, 입력, 목록 줄, 토글, 상단바, 하단 탭, 팝업)과 변수(색, 간격, 모서리), 글자 스타일을 찾는다.
   - 기획자가 서비스 화면 파일 링크를 줬으면 기존 화면 2~3개를 읽어 쓰는 부품과 배치를 맞춘다.
5. 새 피그마 파일을 만든다. 이름: `<과제명> 화면 설계 v<버전>`.
6. `3_결과물/개발명세.md`의 화면별 구성(YAML)을 기준으로 화면마다 프레임을 만든다.
   - 프레임 이름은 `<화면 번호> <화면 이름>`, 크기는 앱 360×800, 웹 1440×1024.
   - 요소는 라이브러리 부품으로 만들고, 없을 때만 직접 그린다. 문구는 구성의 글자를 그대로 쓴다.
   - 팝업 화면은 부모 화면 위에 어두운 막과 함께 그린다.
   - 화면마다 그린 뒤 캡처로 확인하고, 글자가 잘리거나 겹치면 고친다.
7. 화면 옆에 번호와 설명을 붙인다: 화면 오른쪽에 번호별 설명 상자, 요소 위에 빨간 번호. 디자이너가 설명을 보며 다듬을 수 있게 한다.
8. 프로토타입 연결을 단다: 개발 명세의 `navigate`대로 누르면 다음 화면으로 가게 한다.
9. 파일 링크를 `00_과제요약.md`의 "입력 자료" 아래 "피그마:" 줄과 변경 이력에 남기고, 기획자에게 링크와 그린 화면 수, 직접 그린(부품이 없던) 요소를 알린다.

## 그 뒤

- 디자이너가 피그마에서 다듬은 뒤 기획 내용(문구, 요소)이 바뀌었으면, 기획자가 알려 줄 때 `sync`로 기획 원본에 반영한다. 피그마를 다시 그리지 않는다.
