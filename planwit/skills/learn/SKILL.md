# 서비스 익히기

플랜윗이 서비스를 모르면 과제마다 기존 기능과 따로 노는 결과가 나온다. 이 스킬은 서비스마다 한 번 서비스 지식(`<서비스>/서비스지식/서비스지식.md`)을 만들고, 그 뒤로는 바뀐 자료만 더 읽어 갱신한다.

## 경로와 엔진

- 지금 폴더가 플랜윗 작업 공간일 때만 진행한다. 아니면 파일을 건드리지 않고 작업 공간을 열어 달라고 한 줄로 안내한다 (`pw-standards` 9장).
- 이 스킬의 기본 폴더에서 두 단계 위가 플러그인 루트(`PLUGIN_ROOT`)다.
- 엔진 실행: `python "<PLUGIN_ROOT>/engine/run.py" <명령>` (`python`이 안 되면 `py`).
- 자료 폴더는 작업 공간 밖이어도 된다. **읽기만 하고 절대 고치거나 옮기지 않는다.**

## 토큰을 아끼는 원칙

1. 폴더 전체를 읽지 않는다. 먼저 엔진이 파일 이름, 날짜, 크기만으로 색인한다.
2. 색인을 보고 분류마다 꼭 필요한 파일만 고른다. 고른 파일도 처음에는 훑어 읽는다 (`extract --head`).
3. 끝까지 읽는 것은 서비스 소개와 기능 지도처럼 서비스 전체를 설명하는 문서, 그리고 훑어 읽기로 부족한 문서뿐이다.
4. 과제와 관련된 자세한 자료는 과제를 시작할 때 그 과제 낱말로 찾아 그때 읽는다 (`find-docs`). 여기서 미리 읽지 않는다.
5. 그림(화면 캡처)은 색인에 목록만 둔다. 과제에서 필요할 때 이름으로 찾아 보고 `<서비스>/디자인/화면지도/`에 복사한다.

## 순서

### 1. 서비스와 자료 위치

- 서비스: 작업 공간에 서비스가 하나면 그 서비스. 여럿이면 기획자의 말로 고르고, 확실하지 않으면 한 번 묻는다.
- 자료 폴더: 기획자가 준 경로. 없으면 아래처럼 요청하고 기다린다.

> 서비스를 익힐 자료 폴더 경로를 알려 주세요. 폴더 전체를 읽지 않고 파일 이름으로 목록을 만든 뒤 중요한 파일만 골라 읽어요. 폴더는 읽기만 하고 고치지 않아요.

### 2. 색인

```
python "<PLUGIN_ROOT>/engine/run.py" index "<자료 폴더>" --service "<서비스 폴더>"
```

`<서비스>/서비스지식/자료색인.md`가 생긴다 (분류별 후보, 판 수, 고친 날). 다시 익힐 때는 같은 명령을 다시 실행하고 "지난 색인 뒤 새로 생기거나 바뀐 파일"만 본다.

### 3. 읽을 파일 고르기

`자료색인.md`만 보고 고른다. 모두 합쳐 15개 안쪽.

| 분류 | 고르는 수 | 고르는 기준 |
|---|---|---|
| 서비스 소개 | 1~2 | 가장 최근, 회사 전체가 아닌 이 서비스 것 |
| 기능 지도 | 1~2 | IA, 메뉴 구조, 기능 목록. 가장 최근 |
| 기획서 | 3~5 | 최근 1년 안, 판이 많은(자주 고친) 것, 서로 다른 기능 |
| 정책 | 1~2 | 운영 정책, 약관 |
| 지표 | 1~2 | 핵심 지표, 대시보드, 최근 리포트 |
| 사용자 | 1~2 | 페르소나, 리서치, VOC |
| 디자인 | 1 | 디자인 가이드, 문구 가이드 |

- 파일 이름으로 판단이 안 되면 고르지 않는다. 빈칸으로 남겨 기획자에게 묻는다.
- 같은 내용의 판이 여럿이면 대표(가장 최근)만 읽는다.

### 4. 훑어 읽기

```
python "<PLUGIN_ROOT>/engine/run.py" extract "<파일>" --head 4000
```

- 서비스 소개, 기능 지도는 `--head` 없이 끝까지 읽는다 (30쪽이 넘으면 `--head 12000`).
- 작업 공간에 이미 있는 것도 함께 쓴다: `<서비스>/기준본/`, 과제들의 `00_과제요약.md`와 방향 정의, `<서비스>/디자인/화면지도/기존화면_패턴.md`, `회사/규칙.md`.
- 읽기에 실패한 파일은 이유와 함께 빈칸에 적는다.

### 5. 서비스 지식 쓰기

이 스킬 폴더의 `template.md` 형식으로 `<서비스>/서비스지식/서비스지식.md`를 쓴다.

- 모든 내용에 출처(파일 경로와 쪽, 또는 과제 이름)와 상태(확인: 자료에 있음, 추정: 자료로 미루어 봄)를 붙인다. 지어내지 않는다.
- **기능 지도**가 가장 중요하다. 메뉴마다 기능, 상태(출시, 진행 중 과제, 계획), 사용자 여정에서 맡는 역할을 쓴다. 과제는 기능 지도의 빈 곳이나 기존 기능과의 관계로 위치를 잡기 때문이다.
- **사용자 여정**은 하루(언제 앱을 여는지)와 생애(처음 → 익숙 → 이탈 위험)로 쓴다.
- 다시 익힐 때는 바뀐 자료가 건드리는 장만 고치고, 맨 아래 "고친 기록"에 한 줄 남긴다.

### 6. 빈칸 요청

서비스 지식에서 과제 판단에 꼭 필요한데 자료로 알 수 없는 것만 대화로 요청한다 (`pw-standards` 6장 "받을 자료"). 서비스 목적, 주요 사용자, 핵심 지표, 기능 지도의 빈 메뉴가 대상이다. 문체나 세부 값은 묻지 않는다.

### 7. 알림

짧게 쓴다.

- 서비스를 한두 줄로 어떻게 이해했는지
- 읽은 파일 (분류별로 이름만)
- 빈칸 요청
- "과제를 시작하면 이 지식을 먼저 읽고, 과제 낱말로 관련 자료를 더 찾아 읽어요." 한 줄
