# 기획안 피드백

기획자는 기획안을 보며 화면마다 바꿀 점을 그냥 적고, 글자는 두 번 눌러 그 자리에서 고친다. 피드백에는 화면 번호와 요소 번호가 함께 저장되어, 플랜윗이 어디를 고칠지 추측하지 않는다.

## 경로와 엔진

- 지금 폴더가 플랜윗 작업 공간일 때만 진행한다. 아니면 파일을 건드리지 않고 작업 공간을 열어 달라고 한 줄로 안내한다 (`pw-standards` 9장).
- 이 스킬의 기본 폴더에서 두 단계 위가 플러그인 루트(`PLUGIN_ROOT`)다.
- 엔진 실행: `python "<PLUGIN_ROOT>/engine/run.py" <명령>` (`python`이 안 되면 `py`).

## 기획안 열기

1. 과제를 고른다 (말하지 않았으면 가장 최근에 바뀐 진행 중 과제).
2. `serve "<과제>"`를 **백그라운드로** 실행한다. 이 PC 안(127.0.0.1)에서만 열리고 브라우저가 자동으로 열린다. 3시간 동안 쓰지 않으면 스스로 닫힌다. 이미 열려 있으면 `<과제>/.planwit/기획안_주소.txt`의 주소를 알려 준다.
3. 한두 줄로 안내한다: "기획안을 열었어요. 화면을 보며 오른쪽 아래에 바꿀 점을 적어 주세요. 글자는 두 번 누르면 바로 고칠 수 있어요. 다 보시면 저에게 말해 주세요."

## 피드백 반영

1. `feedback "<과제>" list`로 새 피드백을 본다. 줄마다 `번호 | 화면 / 요소 (이름) | 내용`이다. 기획자가 질문에 답한 것은 앞선 질문과 답이 함께 나온다.
2. 피드백마다 기획 원본을 고친다.
   - 위치(화면 번호, 요소 번호)를 그대로 따른다. 요소가 없으면 화면 전체에 대한 말이다.
   - 문구 수정은 구성의 `label`이나 설명의 문구를 그 글자로 바꾼다.
   - 영향받는 다른 원본(설명, 정책, 수용 기준, 다른 화면)도 ID 연결을 따라 함께 고친다.
   - 뜻이 둘 이상으로 읽히거나, 고치면 다른 결정과 부딪히면 고치지 않고 질문으로 남긴다.
3. `validate`와 `build all`을 실행한다.
4. 피드백마다 상태를 남긴다. 기획자는 기획안에서 이 답을 본다.
   - 반영함: `feedback "<과제>" set <번호> 반영함 --note "<무엇을 어떻게 고쳤는지 한 줄>"`
   - 질문: `feedback "<과제>" set <번호> 질문 --note "<물을 것 한 줄, 선택지가 있으면 추천과 함께>"`
   - 이미 반영되어 있거나 할 일이 없으면 닫힘
5. 기획자에게 한두 줄로 알린다: 반영한 수, 질문 수. "기획안을 새로 고치면 피드백마다 답이 보여요."
6. 결정이 생긴 피드백은 `00_과제요약.md`의 결정 기록에 남긴다.

## 하지 않는 것

- 피드백 하나를 고치려고 다른 화면을 새로 설계하지 않는다. 범위나 흐름이 크게 바뀌는 피드백이면 질문으로 남기고 기획자와 대화로 정한다.
- 기획안(.html)을 직접 고치지 않는다. 항상 원본을 고치고 다시 만든다.
