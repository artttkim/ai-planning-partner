# 기획안 피드백

기획자는 기획안을 보며 화면마다 바꿀 점을 적는다. 글자 수정은 엔진이 그 자리에서 바로 반영하고(Claude를 쓰지 않음), 메모는 기획자가 "지금 반영해 줘"를 누르면 플랜윗이 반영한다. 반영이 끝나면 기획안이 저절로 새로 고쳐진다.

## 경로와 엔진

- 지금 폴더가 플랜윗 작업 공간일 때만 진행한다. 아니면 파일을 건드리지 않고 작업 공간을 열어 달라고 한 줄로 안내한다 (`pw-standards` 9장).
- 이 스킬의 기본 폴더에서 두 단계 위가 플러그인 루트(`PLUGIN_ROOT`)다.
- 엔진 실행: `python "<PLUGIN_ROOT>/engine/run.py" <명령>` (`python`이 안 되면 `py`).

## 기획안 열기

1. 과제를 고른다 (말하지 않았으면 가장 최근에 바뀐 진행 중 과제).
2. 이미 열려 있으면(`<과제>/.planwit/기획안_주소.txt`가 있고 그 주소가 열림) 주소만 다시 알려 준다.
3. 아니면 두 명령을 **백그라운드로** 실행한다.
   - `serve "<과제>"`: 이 PC 안(127.0.0.1)에서만 기획안을 열고 브라우저를 띄운다. 3시간 동안 쓰지 않으면 스스로 닫힌다.
   - `feedback "<과제>" wait`: 기획자가 기획안에서 "지금 반영해 줘"를 누를 때까지 기다린다. 누르면 새 피드백 목록을 출력하고 끝난다.
4. 한두 줄로 안내한다: "기획안을 열었어요. 화면마다 오른쪽 아래에 의견을 적고, 다 적으면 '지금 반영해 줘'를 눌러 주세요. 글자는 위의 '고치기'를 누른 뒤 고치면 바로 바뀌어요."

## 반영하기

`feedback ... wait`가 끝났다는 알림을 받았거나, 기획자가 "피드백 반영해 줘"라고 하면:

1. 출력된 목록(또는 `feedback "<과제>" list`)의 피드백마다 기획 원본을 고친다. 줄마다 `번호 | 화면 / 요소 (이름) | 내용`이다.
   - 위치(화면 번호, 요소 번호)를 그대로 따른다. 요소가 없으면 화면 전체에 대한 말이다.
   - 문구 수정이 대기로 남아 있으면 엔진이 정확히 찾지 못한 것이다. 원본에서 찾아 바꾼다.
   - 영향받는 다른 원본(설명, 정책, 다른 화면)도 ID 연결을 따라 함께 고친다.
   - 뜻이 둘 이상으로 읽히거나, 고치면 다른 결정과 부딪히면 고치지 않고 질문으로 남긴다.
2. `validate`와 `build all`을 실행한다. 기획안이 저절로 새로 고쳐진다.
3. 피드백마다 상태를 남긴다. 기획자는 기획안에서 이 답을 본다.
   - 반영함: `feedback "<과제>" set <번호> 반영함 --note "<무엇을 어떻게 고쳤는지 한 줄>"`
   - 질문: `feedback "<과제>" set <번호> 질문 --note "<물을 것 한 줄, 선택지가 있으면 추천과 함께>"`
   - 할 일이 없으면 닫힘
4. `00_과제요약.md` 변경 이력에 한 줄 남긴다 (예: `| 2026.11.24 | 피드백 F001~F003 반영: 메인 알람 카드 아이콘 변경 | 기획안 피드백 |`). 결정이 생긴 피드백은 결정 기록에도 남긴다.
5. `feedback "<과제>" wait`를 다시 백그라운드로 실행해 다음 요청을 기다린다.
6. 대화창에는 한 줄만 말한다: "피드백 N개를 반영했어요. 질문 M개는 기획안에 남겼어요."

## 하지 않는 것

- 피드백 하나를 고치려고 다른 화면을 새로 설계하지 않는다. 범위나 흐름이 크게 바뀌는 피드백이면 질문으로 남긴다.
- 기획안(.html)을 직접 고치지 않는다. 항상 원본을 고치고 다시 만든다.
