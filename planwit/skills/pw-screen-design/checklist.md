# 화면 설계 점검 항목

| 분류 | 점검 항목 | 기준 |
|---|---|---|
| 기존 방식 | 화면마다 `참고 화면`이 있고, 위치·구성·문구·흐름이 그 기존 화면과 같음. 기존 화면이 없으면 검수함에 "기존 화면 확인 필요"가 있음 | 작성 순서 0 |
| 범위 | 모든 화면이 과제요약의 기능(FR)에 필요한 화면임. 요청에 없는 기능 화면(신고, 안내 팝업, 온보딩 등)이 없음 | 과제요약 |
| 연결 | 모든 기능(FR)이 화면 하나 이상에 연결됨 | ID 체계 (엔진 validate) |
| 연결 | 모든 화면에 들어오는 길과 나가는 길이 있음 | 유저 플로우 |
| 연결 | 설명에서 가리키는 화면 ID가 모두 있음 | 엔진 validate |
| 완결성 | 필요한 상태(빈 화면, 오류, 로딩, 권한별)가 빠지지 않음 | 닐슨 휴리스틱 |
| 정리 | 비고가 두 줄 이내이고 상태, 예외, 규칙이 없음. 모양이 다른 상태는 별도 화면, 공통 상태는 공통 정책 ID로 씀 | 작성 순서 3, 4 |
| 완결성 | 번호마다 설명이 있고, 설명마다 번호가 있음 | 엔진 validate |
| 명확성 | 모호한 표현이 없고, 문구는 `TBD`가 아니면 실제 문구 | 작성 기준 |
| 명확성 | 버튼 활성 조건, 이동할 화면, 실패 시 처리가 적혀 있음 | |
| 설명 형식 | 설명이 노출 → 내용 → 동작 → 규칙 → 예외 순서의 항목으로 쓰여 있고, 최소 기준(누르는 요소의 동작, 입력 요소의 규칙, 조건부 요소의 노출, 실패 가능 동작의 예외)을 채움 | 작성 순서 3 |
| 사용성 | 오류 문구가 해당 입력창 가까이에 있음 | KWCAG, 닐슨 휴리스틱 |
| 사용성 | 앱의 터치 요소가 너무 작지 않음 (44pt, 48dp) | Apple HIG, Material Design |
| 일관성 | 같은 동작은 같은 요소와 문구를 씀 | 회사 규칙 |
| PRD | PRD 내용과 어긋나지 않음. 어긋나면 "확인만"에 남김 | 합의된 PRD |
| 와이어프레임 | 화면에 보이는 요소마다 구성 요소가 하나씩 있음. 버튼 여러 개나 목록 여러 줄을 글자 하나로 쓰지 않음 | 작성 순서 2 |
| 와이어프레임 | 나란히 놓이는 요소는 `행`, 묶인 요소는 `카드`나 `묶음`의 `children`으로 씀 | 작성 순서 2 |
| 와이어프레임 | `label`에 화면에 보이는 글자만 있음. 조건, 권한, 동작 설명은 설명 표에 있음 | 작성 순서 2 |
| 와이어프레임 | 만든 장표와 디자인 화면 캡처를 그림으로 보고 글자가 겹치거나 틀 밖으로 나간 곳이 없음 | |
