# 앱 UI/UX 기본 기준

화면을 그리기 전과 그린 뒤에 이 기준으로 본다. 서비스의 기존 화면(`참고 화면`, 캡처)과 다르면 서비스 쪽을 따른다. 기준은 Apple HIG, Material Design, 닐슨 휴리스틱에서 앱 기획에 바로 쓰는 것만 골랐다.

## 1. 사용 맥락이 먼저다

화면마다 `## 비고`에 한 줄로 사용 맥락을 쓴다: `- 맥락: <언제, 어떤 몸 상태, 어디서, 쓸 수 있는 시간>`. 아래 결정은 이 맥락에서 나온다.

| 맥락 | 설계 |
|---|---|
| 막 깸, 졸림, 한 손 | 큰 글자, 누르는 것 하나, 입력 없음 |
| 자기 전, 어두움, 누워 있음 | 어두운 화면(`theme: dark`), 소리 기본 끔, 짧게, 끝은 화면을 끄는 쪽으로. 밝은 화면으로 이어지는 링크를 두지 않는다 |
| 이동 중, 짧은 틈 | 한 화면 한 가지 일, 이어 하기 |
| 설정, 처음 한 번 | 기본값을 미리 채우고 바꿀 수 있게. 설명은 짧게 |

## 2. 화면 틀

- **상태바**: 앱 화면 맨 위에는 상태바가 있다 (엔진이 그린다).
- **상단바**: 한 단계 깊이 들어간 화면은 왼쪽 `뒤로`. 아래에서 올라온 전체 화면(만들기, 편집, 진행)은 오른쪽 `닫기`. 제목은 화면 이름 하나.
- **주요 행동은 하나, 아래에 고정**: 저장, 시작, 다음처럼 화면을 끝내는 행동은 화면 맨 아래 꽉 찬 `기본버튼` 하나. 구성의 맨 끝에 두면 엔진이 아래에 고정한다. 같은 무게의 버튼을 둘 이상 두지 않는다 (보조 행동은 `보조버튼`이나 `텍스트링크`).
- **하단탭바 화면**: 맨 위 화면(메인, 통계, 친구, 설정)에만 둔다. 하단탭바가 있으면 하단 고정 버튼을 두지 않는다.
- **여백**: 좌우 16~20px, 묶음 사이 12px 안팎. 빈 공간이 화면 절반을 넘으면 내용이 너무 적거나 화면을 나눈 것이다 — 합치거나 위치를 다시 본다.

## 3. 부품 고르기

| 하려는 일 | 쓰는 부품 |
|---|---|
| 켜고 끄기 | `토글` (설정 목록이면 `설정줄` + `selected`) |
| 다른 화면에서 값을 고르기 | `설정줄` (`label` 이름, `value` 지금 값, 누르면 이동) |
| 2~4개 중 하나 (바로 바뀜) | `세그먼트` |
| 5개 이상 중 하나 | `라디오` 목록 |
| 여러 개 고르기 | `체크박스` 목록, 순서가 있으면 고른 순서 번호 |
| 시각 | `시간선택` (바퀴). 숫자를 입력하게 하지 않는다 |
| 요일 | `요일선택` |
| 짧은 글 (선택) | `입력창`. 쓰지 않아도 되면 안내 문구에 "선택"을 밝힌다 |
| 묶음의 이름 | `소제목` |

- 누르는 요소는 높이 44pt(iOS) / 48dp(Android) 이상. 엔진 부품은 이 크기로 그려진다. `size: small` 버튼은 보조 행동에만.
- 한 화면에 입력창은 되도록 하나. 입력은 고르기로 바꿀 수 있으면 고르기로.

## 4. 글과 위계

- 화면에서 가장 중요한 것 하나만 `제목`. 나머지는 `본문`, 보조 설명은 `안내문구`.
- 문구는 서비스 말투를 따른다 (서비스 지식 4장). 버튼은 동사로 끝낸다: "시작하기", "저장".
- 한 줄 설명은 한 문장. 같은 말을 제목과 본문에 반복하지 않는다.

## 5. 상태와 길

- 화면마다 들어오는 길과 나가는 길(뒤로, 닫기, 완료 뒤 갈 곳)이 있다.
- 첫 사용(기본값 제안), 빈 상태, 오류, 로딩, 권한 없음 중 이 화면에 생기는 것은 상태 화면이나 공통 정책으로 정한다.
- 되돌릴 수 없는 일(삭제, 그만두기)만 확인 팝업. 그 밖에는 바로 하고 되돌리게 한다.
- 강제하지 않는다: 건너뛰기, 나중에, 끄기를 늘 같은 자리에 둔다. 하지 않았다고 벌주거나 다시 조르지 않는다.

## 6. 서비스 톤 따르기

- 디자인 값은 `<서비스>/디자인/디자인.css`, 배치와 부품 모양은 `참고 화면`과 캡처를 따른다. 기획자가 준 샘플 화면이 있으면 분위기(색, 카드 모양, 버튼 모양, 글자 크기)를 맞춘다.
- 서비스에 이미 있는 패턴(예: 설정 목록 줄 "이름 + 값 >")이 있으면 새 모양을 만들지 않는다.

## 7. 점검 질문 (그린 뒤)

1. 이 화면의 맥락에서 사용자가 1초 안에 무엇을 해야 하는지 아는가?
2. 주요 행동이 하나이고 엄지가 닿는 아래에 있는가?
3. 앱에서 흔히 보는 부품과 배치인가? 서비스의 기존 화면과 같아 보이는가?
4. 빈 공간이나 지나친 글이 없는가?
5. 하지 않을 자유(건너뛰기, 끄기)가 있는가?
